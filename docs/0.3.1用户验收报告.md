验收日期：2026-11-20，香港时间。环境：已安装的 Windows 工作台、已登录的官方 Codex Desktop、原有飞书机器人及飞书 Windows 客户端、Android 官方 API 35 模拟器。手机沿用 0.2.0 APK，电脑升级至 0.3.1。使用明确标记的合成资料，未采集其他人的聊天或应用内容。

结论：日常主链路通过。Windows 随手记、资料选入、飞书交办与续聊、独立专业协作、助理汇总、HTML 看板预览和飞书文件回传已连接起来。手机悬浮入口、真实系统分享及断线补传也已进入同一份电脑资料。物理手机及独立飞书机器人的完整生命周期尚未验证。

## 本次实际发现与修复

1. **“记一下”弹出 Null 异常。** 窗口把输入框命名为 PowerShell 自带的 `$input`，事件触发后拿到错误对象。已修正命名和事件引用，加入失败提示、即时草稿、关闭恢复与升级时退出旧托盘的处理。在实际使用的 Windows PowerShell 5.1 验证。
2. **自动协作后同一文件发两遍。** 原请求和自动汇总都可能发现同一成果。现按一次用户交办、收件目标与文件版本去重；明确的新请求仍可再次发文件。发送事件在网络请求前固定文件快照，失败重试使用原字节和原发送编号。
3. **“继续这个任务”被误当成找历史任务。** 点“继续这件事”后，普通补充现在进入所选任务。已用真实飞书消息复验，继续原 Codex 对话并收到更新后的文件。

## 尚未覆盖与现有边界

- 本次手机是官方模拟器，没有连接 Android 实体机；厂商后台保活、实体扫码、悬浮入口手感和系统权限仍需真机复验。iOS 未实现。
- 飞书真实测试使用已存在并已绑定的主机器人。长期角色在内部建立、派活及并回已验证；创建另一只平台机器人、本人授权、发布审核和实际停用没有完整实测。
- Windows 窗口使用真实控件触发生产事件并连接实际服务；电脑控制工具未能定位其 PowerShell 窗口，所以没有把外部鼠标点击托盘写成已通过。
- 飞书回复的 Markdown 排版仍较朴素；任务成果以可下载文件及工作台预览为准。
- 手机只登记主动输入或系统分享的内容，没有读取小红书正文或微信消息的自动采集能力。多电脑自动互通、P2P、自学习记忆和定时任务中心仍在后续方案内。
- 角色使用会话和资料范围的逻辑隔离，共用同一台电脑及 Codex 工具权限。

验收产生的测试任务已归档，测试阅读角色已并回助理；原业务任务保留。报告与证据不包含账号授权码、应用密钥或私人聊天内容。

## 你接着测试的顺序

1. Windows 托盘点“记一下”，输入一个自己的唯一标题，保存后去工作台“资料”查找；再关窗重开检查草稿。
2. 在飞书给原机器人发 `新任务：我的验收。请计算17乘23，生成一个HTML成果并返回文件。`，观察看板进展并打开成果。
3. 飞书发 `找之前那个我的验收任务`，点“继续这件事”，再说 `继续这个任务，加一句我已验收并返回更新文件`。确认没有新建另一件事。
4. 需要专业协作时，从任务进展页“直接找专业伙伴”进入，再回到总任务看助理汇报。
5. 手机安装 0.2.0 APK，配对后在其他应用上点悬浮“记”；分别试一次系统分享链接、图片，以及断网保存后恢复网络。
6. 在工作台“标记完成”。长期人员变动由助理提出时，确认卡只需要点一次。
