# 伴随首版范围与完整产品路线图

版本提示：本文保留原始规划与历史边界。当前 0.2 的实现范围见 [V2 实现说明](V2实现说明.md)，实际通过与待验收项目见 [验证记录](验证记录.md)。
产品目标是让一个人用最少的记忆、解释和协调成本，把生活与工作持续交给熟悉自己的助手。默认一个助手就够用，专业分工由事情推动。完整产品设计保留，0.1 先验证“留下资料—交办—跨入口继续—看到实际结果”这一条闭环。

## 已实现的页面与衔接

| 页面或入口 | 0.1 实际行为 | 接到哪里 |
|---|---|---|
| Windows 小图标 | 点击弹出文字记录窗；保留草稿与重试编号 | 资料库，不自动派活 |
| Android 记一下 | 文字、链接、图片和系统分享；离线保存、重试与连接设备 | 同一台 Windows 的资料库 |
| 助手首页 | 聊天入口、正在推进、已经交付、最近桌面对话 | 新事项或原事项聊天 |
| 事情 | 按目标查看、查找、分页、归档与恢复 | 事项进展页 |
| 对话 | 按真实桌面对话继续；可载入更早的可读历史 | 同一事项聊天页 |
| 事项进展 | 目标、真实状态、公开进度、子事项、成果快照 | 继续聊天、专业伙伴、原 Codex 对话 |
| 事项聊天 | 原生可见消息与尚未出现在原生历史的本地请求衔接 | 同一事项进展；子事项可返回秘书 |
| 专业伙伴 | 助手、量化、产品、生活方向；直接交流 | 各自事项；最多一层专业分工 |
| 记下的资料 | 检索文字与链接、图片预览、选择资料带入请求 | 助手或专业事项 |
| 关于我的理解 | 明确登记偏好、修正、停用、指定事项范围 | 后续相关请求的上下文 |
| 连接手机 | 安装包、地址选择、一次性配对、已连接设备和撤销 | Android 捕捉入口 |
| 数据与连接 | 真实飞书连接信息、数据导出 | 普通 ZIP、JSON 与附件 |

任务和聊天是同一对象的不同视图。专业角色是工作方式，不是自动建立一个新人的全部人格或独立模型。资料是来源片段，只有明确选入或按需检索后才成为本次上下文；记忆是明确登记、带适用范围的长期参考。

## 一个真实使用日

早上在手机上看到一条露营路线，分享给“记一下”。手机无网也先留住。电脑开机且可达后，记录送入本机资料库。

中午打开工作台，选中路线资料，对助手说“帮我准备周末出行”。简单问题由助手直接处理；需要专业整理时，她可建立生活方向的子事项。首页和总事项显示正在等待哪些专业工作。

下午在飞书用 `/任务` 找到编号，用 `/切换 编号` 接着说“同行人数变了”。消息继续进入同一 Codex 对话。工作台打开该事项，也能读到原对话的实际更新。

晚上打开进展页看准备清单或 HTML 成果。需要细改装备时，直接进入生活伙伴聊天，再返回总事项交给秘书整合。用户不用搬运聊天记录。

## 交互原则

状态使用排队、准备、处理、等待专业工作、取回答复、已交付、投递待核实、失败和暂存等实际含义，不生成虚假完成百分比。只有新一轮确实有最终正文，才把这一轮视为交付。

“暂存安排”只暂存尚未开始的工作。正在实际执行的工作需要在 Codex 原界面停止，工作台会说明原因。切换聊天不丢未发送草稿；重新发送同一次请求不会无声创建两份任务。

专业伙伴完成后，秘书接回结果并整理面向人的交付。专业子事项不继续层层招人；首版最多一层、四个子事项，控制用户难以看见的复杂度。

## 完整产品保留到后续的部分

| 阶段 | 要解决的人的负担 | 交付能力 |
|---|---|---|
| 当前 0.1 | 记不住、换入口要重说、盯不到进度 | 主动记录、同任务接续、工作台、显式记忆、成果 |
| 下一阶段 | 重复整理、反复追问和定时安排散落 | 统一定时安排视图、来源摘要、记忆候选、可校正的自动归纳 |
| 角色阶段 | 专业伙伴身份混在一起、需要自己配置人手 | 长期角色实体、每角色独立机器人、角色私有记忆与权限、秘书创建与管理角色 |
| 设备阶段 | 换电脑、电脑关机、资料在不同设备 | 设备身份、邀请配对、加密同步、同步冲突、执行节点选择与接管 |
| 能力阶段 | 专业工作常重复，却容易形成过多规则 | 多厂商适配、技能候选与版本、效果记录、少量相关技能装载 |
| 长期伴随 | 只能主动讲，适时需要时找不到上下文 | 可选择的上下文来源、时间与情境触发、低打扰秘书汇报、iOS 终端 |

自动收集应按具体来源开关、可看来源记录、可暂停和撤回。它不等于默认读取所有应用。原始片段、事实、助手推断和用户确认必须区分，避免一次误解变成以后所有工作的前提。
