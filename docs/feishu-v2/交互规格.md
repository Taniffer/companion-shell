# 伴随 · 飞书交互 V2

设计日期：2026-11-18。本文与同目录效果图为待实现方案，示例数据均为虚构；不是当前 MVP 已具备的功能。

## 体验主线

默认只有秘书。用户说人话，秘书承担理解、拆解、执行和汇报。稳定、反复出现的专业需求才触发招募建议；临时子任务不额外创建机器人。长期角色对应独立应用机器人，头像、名字、会话和职责明确。

秘书有三个固定菜单：我的任务、记一下、助理。普通输入仍随时可用。专业助理菜单：当前任务、我的任务、找秘书。菜单触发发送最新卡片，避免用户翻聊天记录。没有选中任务时，自然语言由角色识别，涉及多个任务才问一次具体指向。

卡片内主操作最多两个；其他低频操作收进更多。任务始终有标题、负责人、当前状态、最近更新、下一步；用真实阶段和时间说明进展，不编造百分比。对话与任务并存，闲聊不强制建任务，记录不自动变成任务。

## A · 秘书建议招募 → 独立助理接手

1. 用户继续在秘书会话讨论量化研究。秘书发现重复需求，建议“要不要让量化助理长期跟这件事？”卡片列职责、拟交接的具体任务、会使用的相关资料。操作：招募并交接 / 继续由你做。
2. 点击后先确认请求已收，再显示开通进度。只有机器人可用、收发验证通过、上下文交接成功后才显示“量化助理已就位”。需要登录或管理员处理时显示“还差一步”，用户完成平台必要步骤后可继续，不重复丢失招募请求。
3. 就位卡操作：和量化助理聊 / 查看交接。跳转独立机器人会话。跳转本身只负责打开会话；上下文由伴随内部交接记录提供，不依赖飞书自动转送聊天历史。跨应用用户身份单独核验。
4. 量化助理首条消息说明“秘书已把《验证低换手选股假设》交给我”，展示同一个任务、已知约束和下一步。用户直接补充“先做近五年，算上交易成本”，无需重新介绍背景。交接包含相关摘要和必要资料，不是复制所有聊天。

## B · 执行 → 缺信息 → 交付 → 继续

1. 同一任务卡原位更新“运行中”，显示已完成阶段、当前阶段和更新时间。操作：补充要求 / 找秘书。新增要求必须有接收回执，再说明本轮已采用或将在下一轮处理。
2. 需要用户信息时进入“未完成 · 待你补充”，卡片提供原生下拉框/输入框。示例：研究区间、排除范围、补充要求；提交并继续。不得在缺信息时显示正在执行。
3. 提交成功后回显选择并恢复任务。正常重试只产生一次业务操作。校验错误保留用户已填内容；请求超时不能显示已提交。
4. 交付卡给结论、限制和后续选择，报告以飞书文件消息发送，可用客户端原生预览。操作：继续这项研究 / 请秘书汇总。HTML 看板不假装在消息卡内渲染。
5. 找秘书/请秘书汇总延续同一任务，秘书引用专业助理的结论和来源，不重新创建任务。原任务卡保留可追溯记录。

## C · 我的任务 → 详情 → 专业会话；随手记

1. 点“我的任务”，秘书发最新任务摘要卡。角色下拉：全部 / 秘书 / 量化 / 产品 / 生活；状态：运行中 / 未完成 / 已完成。每页少量任务，更多时翻页；顶部总数不因当前页变化。
2. 点任务进入同一会话的详情卡，主操作“和负责人聊”，次操作“补充要求”。看进度不必跳专业会话；需要深入讨论时才跳。负责人离职后跳秘书，不留下死链。
3. Web 大看板提供全屏三列与列表视图；手机默认原生任务卡。仅在设备可达、鉴权有效时展示“打开完整看板”。不能给手机发送电脑的 127.0.0.1 链接，也不把 WebView 当成网络连通方案。
4. 点“记一下”显示轻表单，文字和链接可直接记；图片/文件沿用飞书原生发送，收到后展示登记回执。记录状态为“已保存”，并提供“交给秘书处理”，默认不创建任务。安卓悬浮记录是另一个入口，汇入同一资料池。

## D · 解雇 → 可核对交接 → 并回秘书

1. 用户对秘书说“量化助理先不用了，你接回来”。秘书准备具体交接清单：未完成任务、可迁移记忆、知识与技能索引、成果文件。运行中的工作先进入可交接状态，期间不再给该角色派新任务。
2. 卡片显示交接清单和合并影响，示例“2 项未完成任务、8 条记忆、3 份成果”，用户可展开核对。操作：并回秘书并移除角色 / 暂时保留。长期记忆去重、保留出处和访问范围；知识与技能按需检索，不全部塞进秘书当前对话。
3. 先完成内部任务/资料交接，再停用外部机器人。产品的“移除角色”代表退出活动角色和派单入口；不承诺能擦除飞书历史会话。平台应用停用、删除是分别核验的外部步骤。
4. 成功卡显示“工作已并回秘书”，原任务仍在列表，负责人更新为秘书。若外部停用失败则显示“交接已完成，机器人停用待处理”，可重试，不回滚已经安全完成的资料交接。

## 需要一起设计的状态

| 场景 | 用户看到的反馈 | 后续入口 |
| --- | --- | --- |
| 点击已收到，处理耗时 | 已收到，正在安排；禁止重复提交 | 原卡继续更新 |
| 电脑离线 / 回调无回执 | 飞书可能直接提示操作失败；不显示我们自造的成功回执 | 电脑在线后重试；也可发消息，恢复后核对是否收到 |
| 已持久化请求后断线 | 请求已保存，等待执行设备恢复 | 恢复后继续，不能重复建角色/任务 |
| 消息离线期间漏收 | 不承诺平台无限补投；恢复后主动对账，发现缺口时解释 | 用户重发或明确重新提交 |
| 旧卡失效 | 旧卡只作历史；固定菜单获取最新卡 | 我的任务 / 助理 |
| 平台需要扫码或审批 | 还差平台授权/发布这一步，保留进度 | 去完成 / 稍后继续 |
| 授权给 Codex 的系统操作 | 回到实际 Codex / 系统授权界面 | 飞书业务卡不能冒充系统授权 |
| 群里询问私人资料 | 群内只显示可分享摘要 | 私聊秘书继续 |

## 分工与隔离

专业角色之间按任务、资料、技能授权隔离。秘书能在用户委托范围内管理团队和汇总信息，用户单独设定的私密范围必须保留。不同机器人是一层可见身份；真正的数据隔离还需要伴随的访问控制，不能只靠换头像和提示词。当前 MVP 同一 Windows 账户执行，不是操作系统级安全隔离。

飞书原生任务智能体可作为以后“出现在飞书任务中”的身份扩展；它不等于创建了一个可独立私聊的新机器人。第一轮先完善原生聊天、菜单、交互卡、资料和任务接续，再选做飞书任务同步、云文档与日历。

## 审查后补充的接续规则

- 当前任务按“用户 × 角色机器人”保存。点详情中的“和负责人聊”时，先校验身份、目标任务和授权，写入目标角色的任务选择及交接回执，再打开会话。只打开聊天不代表任务已经选中；绑定未完成时先完成绑定，不假装接续成功。
- 角色下拉动态来自活动角色。文中的秘书、量化、产品、生活是示例，不是硬编码的全部角色。
- “记一下”进入显式记录模式，显示待登记内容预览。文字、图片、文件可合并为同一记录批次，用户点“保存”结束；取消不影响任务。普通对话中发附件时，有明确当前任务则归入该任务；无明确意图才问一次“记为资料 / 用于当前任务”。保存后退出记录模式。
- 每次回调都检查任务、招募单或交接单的当前版本。旧卡只能查看历史或获取最新状态，不能覆盖新决定、重复招人或重复合并。
- 解雇期间遇到运行中工作，提供“等本轮结束 / 去电脑处理 / 取消交接”；当前执行器未实现可靠停止时，不提供一键强停。确认本轮结束并完成交接后才切换负责人；旧执行晚到的结果只能归档，不再产生新派单。平台停用失败时，旧机器人若仍可收发只提示“角色已并回秘书”，引导打开秘书，不启动第二份执行。
- 同一决策只通知一次：用户在专业会话已处理的事项同步给秘书总览，不重复追问。专业进度主要在原会话原卡更新；跨领域摘要、待用户处理事项和重要结果由秘书集中汇报。用户能随时选择仅秘书通知。
