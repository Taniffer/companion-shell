# 伴随 · 助理自动分工方案

你平时只找一位「助理」。交代目标后，助理负责理解、安排、检查和收尾。过一阵想起来，用记得的任何线索找回原任务，接着说就行。

上一版让你确认招募、看名单、开通机器人，才能完整体验专业分工。新版把组织工作交还助理。看板的主角始终是你关心的事。你对工作方法有兴趣时，可以打开任务里的参与者或直接找协作者聊。

## 你每天怎么用

| 你要做的事 | 看到什么 |
| --- | --- |
| 交代一件事 | 发一句话。能当场完成就当场答，需要跟进的就立为任务，返回一句对目标的理解和进展入口。助理根据已有信息开工。 |
| 随手记一个帖子 | 「记一下」只保存你交给它的内容。以后用原词、来源或印象找出来，再决定是否交给某件事。 |
| 找回之前的事 | 在飞书或电脑说“找上周那个低换手回测”，看到任务、最新进展和可打开的成果。匹配有歧义时，给最多两个带日期和结果摘要的候选。 |
| 继续原来的事 | 在任务页、原飞书卡片或找到的任务里加一句要求。助理沿用该任务的约束和成果。新的计算结果保留版本。 |
| 扫一眼全局 | Windows 保留「运行中、未完成、已完成」大看板。顶部能搜索、交代和查看需要你决定的事。保留方便的角色筛选、任务列表、对话与成果入口。 |
| 深入问专业细节 | 任务详情显示当前结论、下一步、成果，以及实际参与者。点参与者聊，留在同一件事。回到助理时，已经明确的新要求和专业结论能接上。 |

飞书承担随手交代、查找和收结果。Windows 用于看多件事、检查进展和打开 HTML 等交付。Android 入口保持一个「记」图标。跨入口接续的锚点是任务及其成果，同一项工作始终能从原任务接续。

助理只主动汇报影响你下一步的事，例如成果可用了、原计划需要改变、确实需要你选一个方向。普通分工、调度与可自行恢复的尝试留在任务过程里，想看就能展开。

## 助理如何决定增减人手

助理根据你交代过的任务、追问、改过的要求和实际复用的资料判断近期需求。这些证据来自你已交给它且获准用于相应工作的内容。比如你连续发来好几个量化链接，这时它会积累资料。你又在多件不同的事里反复要求按同一套口径回测，并持续追问，这才有了判断长期需要的证据。

| 工作情形 | 助理的决定 |
| --- | --- |
| 目标简单，自己能交付 | 直接做。 |
| 已经有合适的协作者 | 找现有的人接活，把这件事的目标、资料和验收条件交过去。 |
| 首次遇到复杂事项 | 按需要临时分工。比如同一件事分别验证回测数据、制作 HTML。助理检查结论与页面一致后，交付一份完整结果。 |
| 多件事持续复用专门背景、积累有效方法 | 助理决定人选与职责，发一张卡请你确认。你点同意，助理创建长期角色，安排工作。 |
| 阶段结束，或者职责重叠 | 助理列明影响，请你同意一次。手上的活结束后，助理接回任务、记忆和资料，保留来源与成果。 |

是否建立长期角色，看三件事。需求是否跨多个独立任务持续出现。这个角色能否沉淀清晰、可复用的专业方法。以后节省的解释、返工和检查，是否值得维持它。具体次数只是信号，明确的长期委托可以更早安排。一次反复修改同一件事，整理那件事的项目记忆就能减轻负担。边界模糊时先用临时协作，积累证据后再决定。

助理始终对任务负责。执行的人可以变，任务仍然可查。它分派时交代目标与交付标准，接回时检查结果、合并冲突、更新任务。你可以直接说“这次你自己做”“让上次做回测的人接着做”。这也是普通的任务指令，助理负责落实。

## 怎样避免一份越来越厚的记忆

记忆存得多和每次带得多是两个问题。用长期角色保存有价值的专业积累，同时让每次执行只带当前任务需要的内容。

| 放在哪里 | 保留什么 | 用到时怎么取 |
| --- | --- | --- |
| 助理的常用摘要 | 稳定偏好、当前优先事项、哪些事正在推进、去哪里找详情 | 保持简短。优先用你明确确认或反复采用的偏好。 |
| 项目与任务 | 本轮目标、已定口径、关键决定、下一步、材料和成果版本 | 续聊时先读当前摘要，遇到细节按来源打开。共用的是同一份任务记录。 |
| 专业角色 | 能跨任务复用的方法、教训与适用条件 | 专业执行时按相关性调用。单次要求和中间过程归任务。 |
| 原始资料与对话 | 你记下的原文、分享链接、已授权的对话记录、文件 | 用于查找和追溯。带进任务前按权限和相关性选择具体片段。 |

每次给协作者的工作交接包含目标、已定约束、必要资料和需要交回的结果。工作结束后只回收结论、依据、有用的下一步和成果链接。两位协作者需要配合时，就共享那一项决定或那份文件。助理维护它们的位置和适用范围。

例如“这次露营预算 800”留在当次任务。你几次明确要求“回测始终计入交易成本”，助理可以把它记成量化工作的稳定口径，并保留依据。你后来修改口径，从下一次适用工作开始使用新决定，旧结果仍能查到当时的规则。角色合并也沿用这些范围。

## 飞书什么时候出现独立机器人

飞书的日常入口叫「助理」。在既有授权范围内，助理可以先安排临时协作，任务立即推进。长期成员变动给你一张确认卡，网页或飞书确认一次等效。任何实际参与者都能从任务详情打开自己的对话。

当你有长期从飞书直接找某个角色的需求，独立入口才有使用价值。已经开通的角色用各自的机器人身份。助理处理配置，飞书要求账号本人确认时，提示的内容是“开通这个飞书直聊入口”。任务继续推进，开通完成后入口可用。

需要你判断的是目标和实际权限。比如两个目标互相冲突、工作需要使用尚未授权的资料或对外执行超出现有委托的动作。此时只问会影响结果的那个决定，并继续做与它无关的部分。

## 用一件事验收

1. 你在飞书说“回测一下低换手策略，给我一个能打开的对比页”。助理建立一张任务卡，从已有授权范围内自行安排回测和页面，回传最新进展与成果。
2. 第二天打开 Windows，说“昨天那个低换手，交易成本也加进去”。找到原任务并继续，旧报告还在，新版本从同一个地方打开。
3. 想问回测方法时，从这张卡直接跟实际做回测的人聊。回到助理，能接上你们刚才定下的口径。
4. 几周后确实出现多项相关工作，助理给出一张长期量化协作建议，你点一次同意，它就安排好。你仍在原来的地方交代事情，也能按角色筛选任务、查每一份成果。
5. 这个方向暂停后，助理建议并回。你确认一次，助理自行接回在办事项与可复用的知识。隔一段时间仍能用你记得的标题、时间或成果找到它，接着用当时的资料或按新要求更新。

下一版先改这三处。面向你的名称统一为「助理」。日常派发、汇总、交接都由助理安排。增减长期人员时留一张能直接同意的卡，任务页可以随时追问。把跨入口查找、指向原任务的续聊，以及任务摘要与专门记忆的按需调用做成完整链路。验收看交代后能否直接开工、跨入口能否找回原任务、续聊需要重说多少，以及长期协作有没有持续提高交付质量。
