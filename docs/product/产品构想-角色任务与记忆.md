# 伴随式 AI 伙伴：角色、任务与记忆

讨论稿 · 2026-11-16 · 先明确产品体验，再构想技术实现

## 当前共识

继续使用模型厂商提供的 CLI 或 Desktop，把模型能力留给厂商维护。产品负责随处接入生活上下文、提供可用工具、保留任务与成果、积累可迁移的记忆和经验。

默认是安静的“记一下”小图标，点击即可保存当前片段，不必先打开角色、任务或聊天面板。完整交互由另外的终端承担。支持多位帮手，既能按角色找人，也能直接按事情看进度。设备和模型变化后，个人积累应能继续使用。

补充一位长期理解用户的秘书：面向用户负责汇报、建议和后续跟进，面向专业伙伴负责协调、交接和整合成果。用户可以直接找任何专业伙伴；同一任务的有效决定与进展回到总览，无需用户转述。秘书的丰富 GUI 位于交互终端，轻入口继续保持“记一下”。完整职责与产品情景已整理到同目录《个人AI秘书与专业伙伴-产品方案》。

开源、客户端之间互通、使用者免部署独立业务服务端、自己的手机入口、多电脑和跨 Agent，是后续技术方案必须考虑的约束。之前讨论过的具体通信组件均为候选，不作为当前已确定的技术方案。

## 一、从人的需求出发

| 人的需求 | 产品应该做什么 | 应避免的负担 |
|---|---|---|
| 随手放下一个念头 | 一句话、链接、截图可以先保存 | 保存前就要选角色、项目、标签和截止时间 |
| 知道事情有没有推进 | 直接看状态、成果、卡点和下一步 | 为了看进度先找角色再翻聊天 |
| 重新进入一件事 | 带回目标、已做决定、当前停点与相关资料 | 读完所有历史才能接着做 |
| 找到熟悉可靠的帮手 | 保留角色的专长、工作习惯与协作经历 | 每件小事都新建一个角色 |
| 让不同帮手相互配合 | 共享相关事实、约束、成果与知识线索 | 把所有角色的完整对话混在一起 |
| 经验持续积累 | 提炼可靠做法、修正旧记忆、按需使用技能 | 每次失败后多加一条永久规则 |
| 保持主导权与安静 | 小图标、按需唤起、可纠正与可暂停 | 新资料不断变成提醒或待办 |

下面的研究可作为设计依据，但具体产品结构是我们的推导，不能视作研究已经证明了这个 AI 产品有效。

## 二、五个概念分别解决不同问题

### 伙伴／角色：我习惯找谁

角色保留长期分工、专长、表达方式和合作习惯。量化帮手、产品帮手、生活帮手可以是首批角色示例。

角色与模型品牌分开：同一角色以后可以由不同厂商工具承接；同一模型工具也可以承担不同角色。用户不必因更换模型重建所有合作积累。

一位角色可以参与许多事情，分别带着当前需要的上下文。角色不应只有一条无限增长的大聊天。

### 领域／项目：我持续关心什么

量化研究、个人软件、生活安排是持续领域；某个策略、这款客户端、某次旅行可以成为具体项目。项目收拢长期目标、约束、决定、文件和成果。

角色与项目是可交叉关系。产品帮手可以为量化研究设计看板；量化帮手可以为产品提供数据验证要求。

### 任务：这次要推进什么

任务有明确目标、状态、负责人、下一步、相关资料和完成依据。任务可以拆成小任务，也可以暂停、等待、转交。

一项任务可以有主负责角色和协作角色。默认让用户知道谁在推进、谁提供了帮助，不要求每次多角色齐上阵。

对话记录参与过程；一项任务可能跨多段对话，多项任务也可能源自同一段讨论。看任务进度不应依赖翻聊天。

### 片段：刚才遇到了什么

片段是一条原始线索：小红书笔记、微信中的一句话、某次聊天的纠正、一个想法、一次操作结果。它保留来源、时间和当时背景。

片段可以先独立存在，日后再关联任务；也可能同时对两个项目有用。分享一个营地不自动代表已经决定去，看到一个策略也不自动代表认同它。

### 记忆：哪些信息值得以后继续使用

记忆是在原始线索上形成的可复用事实、偏好、决定和经验，带出处、范围、时间与不确定性。明确的用户要求可以直接记住；推测先保留为候选，重复出现也不必然变成事实。

更晚的明确纠正可以更新现行理解，同时保留过去状态。用户能够说“那只是上次的情况”“以后都这样”“这条忘掉”。

## 三、聚焦任务和片段记忆确实需要区分

它们分别满足“把事情推进”和“把东西接住”两种需要。

- 聚焦任务：当前目标、已有决定、完成情况、阻碍、下一步与本次相关资料。
- 保存片段：先留住线索，允许暂时没有目的、没有负责人、没有截止时间。

任务可以引用已有片段；任务执行也可以产生新的片段和经验。片段只有在出现明确行动意图时，才需要转成任务。系统可以建议关联或行动，用户不用为了保存资料先管理一遍项目。

每次离开任务，留下简短的“接续位置”：已经到哪一步、下一步是什么、什么还没确定。回来时先恢复这些信息，再按需要找更多历史。

## 四、记忆同时有“用途”和“适用范围”

按用途区分：经历记录、事实与偏好、当前工作状态、可复用做法。它们需要不同的更新方式。原始经历可以保留，而从中提炼的结论可以被修正。

按范围区分：

| 范围 | 示例 | 取用方式 |
|---|---|---|
| 个人共有 | 主力设备、喜欢怎样读成果、明确长期偏好 | 各角色在相关情境下使用 |
| 领域经验 | 量化研究的资料核验口径、创作的连续性经验 | 在相关领域工作中使用 |
| 项目决定 | 这款软件采用伴随式、小图标为默认入口 | 在该项目的不同角色和任务之间共享 |
| 任务现场 | 这次正在比较哪几个方案、还卡在哪里 | 当前任务优先使用，结束后归档 |

这些不是互斥文件夹。一条经验可以有多个适用范围；共有也不意味着每次都要拿出来。

因此，“上下文”是当前角色为当前事情选出的工作资料：相关共同背景、领域经验、项目决定、任务状态和必要片段。它随焦点变化，不等于角色全部历史。

迁移时带走个人与领域记忆、项目和任务状态、来源线索、技能及其适用说明。不能把厂商模型内部状态视作可直接迁移的个人记忆。

## 五、角色之间怎样串通

建议采用“共同背景＋领域分工＋按任务共享”。

秘书负责跨角色的协调，但不成为所有交流的必经入口。用户可以在量化、产品、生活等专业对话中直接改变任务安排；新的有效决定应改变该任务的后续协调。共享以相关任务状态、成果、明确决定和必要背景为主，日常闲聊和局部猜想不自动广播为全局命令。专业分歧保留依据，由秘书说明对用户选择的影响。

例如，量化帮手形成一个明确的图表数据口径，产品帮手做看板时引用这条口径及出处；生活帮手知道用户需要远端方便查看成果，产品帮手设计下载入口时引用这条偏好。它们无需拿到对方全部聊天。

共享行为最好可见：“这次采用了量化研究里的数据口径”“这条阅读偏好来自之前的短片交付”。用户可以纠正关联，或将某条信息限定在原来的项目。

职责变化也要保留记录，避免大家以为别人会做。用户既能按角色看其参与的事情，也能按任务看所有参与者与成果。

## 六、轻入口和交互终端分别服务不同意图

最新纠正：之前将“看进度／随手记／找帮手”塞进微面板，已经让轻入口承担了过多选择。轻入口应优先收窄到“记一下”，多角色和任务管理移到交互终端。

复杂度按当时的意图和可投入注意力决定。同一部手机也需要快速分享，同一台电脑也可能需要完整查看任务。

| 使用状态 | 人当时要什么 | 产品行为 |
|---|---|---|
| 顺手保存 | 先别丢，之后还能找回 | 一次操作保存，不要求分类或建立任务 |
| 快速确认 | 看看做到哪，是否需要我 | 直接展示状态、卡点、下一步和结果 |
| 主动处理 | 讨论、比较、决定、安排 | 支持长对话、角色协作、任务组织与记忆修正 |

电脑上的小图标承担第一种状态：不闪烁、不自动弹大面板，不显示一串待办。点击后的回执应简短说明实际保存了什么，并允许撤销。选中内容与当前页面的保存规则需要清楚，不能因为追求一步完成而让用户猜测。

用户可以额外补一句话，但不应被要求先指定角色、项目、标签或截止时间。保存片段本身不创建任务。系统后台形成的近期线索和用户主动记下的资料应能区分；后者说明用户认为它值得保留，不代表已经认同内容或决定行动。

交互终端可以承载“看进度、找帮手、继续处理、查看产物、整理记忆和技能”。按事情和按角色两种查看方式都保留。进度以完成内容、卡点和下一步为主，没有可测量依据时不制造百分比。

手机既可以把内容分享进来，也可以作为完整交互终端；后者允许更丰富，但默认先展示当前最相关的事情，复杂操作再展开。

### 飞书与自研客户端的产品定位

产品目标是让终端可选择。飞书适合沿用已有消息习惯，独立客户端适合长期查看和组织角色、任务、记忆、技能与产物。终端切换后，应能认出同一件事、看到同一状态并取用相同范围的个人积累。

建议独立客户端承载完整产品体验，飞书作为可选消息终端。使用者可以按习惯选择，不要求人人使用飞书，也不要求每次从飞书复制内容到另一处。具体各终端的功能形式与实现范围，在产品流程明确后再决定。

“轻入口只负责记一下”不代表产品只有采集能力。终端必须让片段能够被找回、关联和用于实际任务，否则只是增加一堆无人处理的收藏。

角色可以逐步增加；不因用户出现一个新话题，就自动生成永久角色。

## 七、技能如何增长而不增加负担

技能是验证过的可复用做法，附带适用条件、结果例子、限制与版本。角色知道去哪里找适用技能，不必把全部技能始终带在身上。

一次任务成功后先留下经验；可复用的做法再形成候选技能。对于相似、冲突或过时的做法，支持合并、替换和退役。用户纠正一次输出，不自动增加一条全局永久禁令。

评价成长时看：重复解释是否减少、重新接续是否更快、是否找到正确资料、相同工作是否更少返工。技能数量只能说明收藏规模，不能证明能力变好。

## 八、研究依据与推导边界

### 活动导向计算

Bardram 的 Activity-Based Computing 工作将服务、资料与参与者围绕活动组织，并讨论暂停恢复、跨设备继续与协作。这支持让用户直接找回“正在做的事”，而不是逐个重新拼应用窗口。

产品推导：事情是连续性的重要单位，角色和软件作为参与者或工具；任务应能保存接续位置。

来源：[The Activity-Based Computing Project，2011](https://cdn.aaai.org/ocs/ws/ws0689/3865-16601-1-PB.pdf)。

### 多重记忆系统

记忆研究区分事件性、语义性和技能相关的记忆系统，提示“发生过什么”“知道什么”“会怎样做”并非同一种功能。

产品推导：片段记录、可修正结论和技能分开管理；这种结构借鉴功能区分，不宣称软件等同于人脑。

来源：[Squire，Memory systems of the brain，2004](https://www.sciencedirect.com/science/article/pii/S1074742704000735)。

### 交互记忆

Wegner 等人研究人与人如何形成分工，并了解对方掌握什么信息。研究同时提示，扰乱既有知识分工可能带来干扰。

产品推导：伙伴有专长，也知道相关知识可以去哪里找；协作共享必要资料，职责变化要清楚。这是对人类研究的设计借鉴，不能直接证明多个 AI 的效果。

来源：[Transactive Memory in Close Relationships，1991](https://dtg.sites.fas.harvard.edu/DANWEGNER/pub/Wegner%2CErber%2C%26Raymond1991.pdf)。

### 注意力残留与恢复计划

Leroy、Glomb 的研究讨论任务中断后的注意力残留，并在研究条件下发现，为返回旧任务做一个简短计划可以缓解影响。

产品推导：先接住片段，减少被迫切换；为离开的任务保存下一步和未决事项。不能据此承诺任意 UI 都必然提高效率。

来源：[Tasks Interrupted，2018](https://pubsonline.informs.org/doi/10.1287/orsc.2017.1184)。

### 人与自动化共同发起交互

Horvitz 的设计原则强调对用户意图不确定性的处理、介入时机、调用与终止的便利性，以及误判后的修正成本。

产品推导：安静的小入口、显式唤起、低成本纠正与可撤回的关联，是值得测试的设计方向。

来源：[Principles of Mixed-Initiative User Interfaces，1999](https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/)。

### 认知卸载

Risko、Gilbert 的综述讨论人如何借助外部行动与记录改变任务的认知要求；Gilbert 的意图卸载实验也研究了外部提醒怎样帮助保留待执行意图。

产品推导：用户在“记一下”时需要暂时放下记忆负担，记录动作应少做判断；保存回执和日后找回同样重要。研究不直接证明一个图标或特定点击数是最优设计。

来源：[Cognitive Offloading，2016](https://samgilbert.net/pubs/Risko2016TiCS.pdf)；[Strategic offloading of delayed intentions，2015](https://journals.sagepub.com/doi/10.1080/17470218.2014.972963)。

### 平静技术与信息理解过程

Weiser、Brown 的平静技术设计论述强调技术在注意力边缘与中心之间适当转换。Pirolli、Card 对分析工作的研究区分获取资料、组织表示、形成理解和产出。

产品推导：轻入口保留低关注度，用户主动处理时终端再展开；采集时无需完成所有整理。但“只记录不回访”也不构成完整的帮助。此处借鉴研究视角，具体终端布局仍需按日常情景验证。

来源：[Designing Calm Technology，1995](https://calmtech.com/papers/designing-calm-technology)；[The Sensemaking Process，2005](https://andymatuschak.org/files/papers/Pirolli%2C%20Card%20-%202005%20-%20The%20sensemaking%20process%20and%20leverage%20points%20for%20analyst%20technology%20as.pdf)。

## 九、下一轮应验证的产品情景

- 不指定角色，丢进一篇笔记，随后能在相关事情中找回。
- 只想看任务进度，几秒内找到卡点，不必和角色寒暄。
- 同一帮手处理两个项目，分别恢复各自背景。
- 量化帮手与产品帮手共同完成研究看板，共享数据定义，保留分工。
- 一次性的情况没有污染长期偏好；用户改主意后，旧结论被清楚更新。
- 换模型或设备后，已有记忆、任务进展和可复用做法能继续用。

这些情景聊清楚并形成可接受的交互后，再决定技术实现。

具体使用过程继续记录在[从“记一下”到伙伴接续](产品流程-从记一下到任务接续.md)，包括片段如何回来、终端怎样看进度、何时形成任务，以及多角色怎样减少用户的协调工作。
