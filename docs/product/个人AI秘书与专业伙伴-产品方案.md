# 个人 AI 秘书与专业伙伴：产品构想

讨论稿 · 2026-11-16 · 本轮明确人的需求、产品职责与交互，技术实现另行讨论

更新 · 2026-11-17：默认一位简单助手即可独立使用；是否安排专业伙伴由助手按事情判断。完整页面、跳转和日常流程另见《页面与交互流程-从简单助手到专业协作》。

## 一、产品承诺

一位持续理解你的私人秘书，带着一组可直接交流的专业伙伴，帮助你记住、推进、完成生活和工作中的事情。你可以交代一句话，可以亲自深入某个任务，也可以暂时不管；再次回来时，事情仍能接上。

秘书对你负责，承担协调和跟进。专业伙伴对各自的分析与交付负责。你始终可以直接找任何伙伴；秘书通过共享的任务进展保持总览，无需成为每次交流的必经入口。

对参与工作的 Agent，助手承担老板职责：确定目标、选择人手、分配工作、控制投入、检查交付。用户不用先配置团队，也无需选择简易模式或专业模式；专业分工和管理深度按实际需要展开。只需要一位助手的人，可以一直保持简单。

日常默认只有一个“记一下”的轻入口。聊天、总览、对照、审阅、计划与管理放在完整交互终端。现有模型厂商的 CLI／Desktop 继续是专业工作的实际场所。产品为它们补上生活入口、连续上下文、个人记忆、协调与可见的进展。

## 二、从人的“懒”理解需求

这里的“懒”可以具体理解为希望降低处理事情的总心力，同时保留掌控感。它包含多种负担，增加聊天能力只能解决其中一部分。

| 人承担的负担 | 产品应替人接住什么 | 可以感知的变化 |
|---|---|---|
| 记住 | 约定、未完成事项、未来适时需要的信息 | 不用靠脑子一直惦记 |
| 找回 | 见过的材料、上次成果、决定的依据 | 用模糊描述也能找回，并能回到出处 |
| 重新解释 | 背景、偏好、已经否定的选项 | 换设备、换伙伴后能接着说 |
| 选择 | 此刻做什么、找谁、采用哪个方案 | 默认有合理建议，关键差异清楚 |
| 协调 | 交接、依赖、优先级、版本变化 | 不用在人和工具之间搬运消息 |
| 盯进度 | 谁在做、哪里停了、有没有交付 | 不必反复追问，停住时有原因和下一步 |
| 判断 | 一堆分析如何变成自己的决定 | 得到建议、理由、代价和待确认点 |
| 修正 | 误解、过时记忆、错分任务、失败操作 | 一次纠正能在相关工作中生效 |

因此，产品需要同时服务三种人类体验：低负担的开始、低成本的恢复、可预测的委托。用户今天想亲自研究、明天想全部交代，均应自然成立。

## 三、秘书的双面职责

面向用户，她是熟悉你的秘书；面向专业伙伴，她是协调者。两面围绕同一件事工作：让你的意图变成有依据、可交付、可继续的结果。

| 对你表现为什么 | 她在背后需要承担什么 |
|---|---|
| 听得懂简短交代 | 结合当前目标和历史决定补齐背景，只问会改变处理方向的问题 |
| 知道你当前最在乎什么 | 协调任务优先级、期限和依赖；遇到冲突给出取舍建议 |
| 找得到合适的帮手 | 按需要选择专业伙伴，给出目标、相关材料与交付要求 |
| 不需要你传话 | 把相关的新决定、材料和进展带到同一任务中 |
| 事情有人继续跟 | 观察停滞、缺材料和执行结果，在约定范围内继续处理 |
| 汇报让你省力 | 检查成果是否回答了原问题，整合证据、差异和建议 |
| 越用越合拍 | 记住有效的协作习惯，让你的纠正改变后续行为 |

秘书可以对结果做完整性检查，但专业准确性需要相应的证据或验证。量化伙伴和产品伙伴有分歧时，应保留各自依据、说明分歧如何影响决定；秘书不应为了给出单一答案而抹掉不确定性。

简单工作直接处理即可。拆任务、增加伙伴、组织讨论都应有可见收益。用户无需管理一群角色的日常运转。

## 四、直接找伙伴必须是一等体验

保留四条自然路径：

1. 向秘书交代目标，由她组织后续。
2. 直接打开量化、产品或生活伙伴，深入交流。
3. 从一件事的页面进入参与该任务的任一伙伴对话。
4. 从厂商原生 Desktop 继续工作，随后在总览中接上相关进展。

例如，你先让秘书安排量化研究，随后直接对量化伙伴说“先比较两个参数，其他先停”。这项任务的目标和当前安排应更新，秘书以后按新安排协调；不需要你再转述一遍，也不能另开一份重复工作。

同步的核心是任务目标、明确决定、进展、交付物和相关依据。日常闲聊、随口猜想和局部草稿不自动变成全局命令。你也可以将某段对话限定在当前任务，或明确说“这条以后都记住”。

任务是连续工作的载体。角色是一种关系和专业入口；同一角色可以有多个任务，每个任务使用自己所需的上下文。一个任务也可以由多个角色参与。

## 五、“越来越理解我”应体现在行为上

认识你的依据需要区分用途和适用范围。

| 层次 | 包含什么 | 应如何影响服务 |
|---|---|---|
| 个人长期偏好 | 表达习惯、成果阅读方式、相对稳定的取舍 | 在相关场景中作为默认值，可修改、可迁移 |
| 当前处境 | 近期关注点、时间安排、正在变化的约束 | 服务当前阶段，到期或变化后更新 |
| 协作约定 | 哪些事可自行处理、什么时候汇报、怎样算完成 | 影响秘书与专业伙伴的具体行为 |
| 领域与项目 | 量化研究口径、软件方向、生活计划 | 留在相关领域，跨领域时按需要共享 |
| 原始经历与材料 | 对话、页面、截图、文件、片段 | 提供证据；按需找回，允许只归档 |

必须区分“看到了”“特意保存了”“表达过偏好”“已经决定了”。浏览一篇露营笔记只能说明见过；收藏不等于准备出行；一次“预算紧”也不能永久定义消费习惯。系统推测应保持可纠正，用户明确表达和实际决定具有不同于推测的地位。

共享记忆提供相关背景；聚焦任务保留当前目标、有效决定、进展与下一步。完整历史随时可追溯，当前工作不必反复加载所有旧内容。

秘书越来越懂你的可观察标准包括：少问重复问题；能分清一次性要求和长期偏好；你改主意后不继续引用旧方案；知道什么时候适合打断你；一次纠正在其他相关伙伴那里也有作用。温和的人格可以提供熟悉感，服务依据仍来自可追溯的事实和明确约定。

## 六、主动程度按事情与阶段确定

搜集资料、分析、提出选择、实施行动可以分别委托。用户可能希望研究全自动完成，却亲自决定最终采用哪个方案；也可能把已明确的重复流程交给秘书持续处理。

| 用户自然的说法 | 产品应理解的委托方式 |
|---|---|
| 先帮我了解清楚 | 研究并整理结论，形成可比较的选项 |
| 这类事以后按约定处理 | 在约定范围和可用能力内继续完成，反馈重要结果 |
| 关键取舍再问我 | 自行解决常规问题，需要用户价值判断时带建议来问 |
| 先放着 | 保留背景与恢复线索，停止无意义催促 |
| 这件事我自己来 | 允许直接接管、修改、停止，并保持状态连贯 |

这些表达用于说明产品应支持自然的委托，具体边界仍需从当前交代与已有约定确定。不能把“了解清楚”扩大成未经交代的现实承诺，也不应对已经授权的每个常规步骤再次询问。

主动服务可以从整理相关材料、提示冲突、给出建议逐渐增加。对不确定意图，先完成容易修正、已获授权的部分；关键问题集中成一次简短的判断。用户表达不想继续后，降低主动程度并保留恢复入口。

## 七、汇报必须替你完成整理和判断

常规汇报优先回答：发生了什么变化；对你有什么影响；建议怎么处理；是否需要你决定；依据和成果在哪里。无需决定时，不强行制造一个问题。

示例：量化伙伴已完成两组参数比较，其中一组换手更低，但这一轮还没有纳入交易成本。因此秘书应解释结果适用到哪里、建议补做什么，以及是否需要改变研究方向。不能只报“研究已完成”，也不能让用户阅读整份日志才能理解局限。

任务状态要有依据：正在处理、等待外部条件、需要用户选择、已交付、暂存。每种状态都能看到更新时间和下一步。没有可测量依据时不制造进度百分比。无法确认是否仍在运行时，显示最后已知状态与时间。

跨设备的体验应延续同一事项：手机已处理的决定，电脑不应继续催；设备暂时离线时，保留未同步的清楚提示。秘书应知道自己的信息覆盖到何处，不能把尚未取得的微信消息、页面或外部结果当成已知。

## 八、GUI 分为三个深度，轻入口保持独立

### 第一层：秘书首页

没有持续事项时，首页以助手对话和少量近期交流为主。出现持续工作后，再按需要增加四类内容：需要我决定、正在推进、已可使用的成果、与我有关的重要变化。页面不展示空的分类，也不要求使用者先招人。

首页保留可直接聊天的入口。卡片有明确动作，例如“按建议继续”“看差异”“稍后处理”“打开成果”“找参与者”。没有相关内容时允许安静，不用未读数量和待整理收藏制造额外负担。用户主动查看时，也能进入所有任务、对话和领域。

### 第二层：一件事

围绕目标、当前有效决定、进展、下一步、参与伙伴、材料与成果展开。聊天是其中一部分；随时能直接找到上次的产物和修改理由。

“请秘书协调”和“直接找专业伙伴”并列。用户点进原生工作对话继续处理时，不必重复讲背景。

### 第三层：完整管理

按需查看所有角色、对话、项目、定时任务、设备、信息来源覆盖、记忆和技能。定时事项需看得到运行安排、最近结果和停止入口。记忆能查看出处、修改、限定范围、删除和导出。

多角色工作图、原始工具日志、详细执行记录可以用于排查和深入理解，默认首页围绕用户的事情组织。

### 独立的轻入口

“记一下”图标负责接住眼前内容或一段话，给短暂回执和撤回机会。无需先选角色、标签或项目。后续可自动建立候选关联，用户需要时才展开。秘书首页承担丰富交互，不能反向把记录动作变成管理流程。

## 九、飞书、自研终端和原生桌面共存

飞书可以承接消息、语音、分享、简短汇报和关键选择。自研终端承载完整总览、任务恢复、对照、成果、对话列表、定时事项和记忆管理。模型厂商原生 CLI／Desktop 承担其擅长的专业工作体验。

三种入口围绕同一批个人事项协作。入口切换时无需搬运上下文，用户在任一处作出的有效任务决定能被其他入口接续。手机方案不以官方模型厂商手机应用为前提。

已有飞书桥接属于可以沿用的基础；完整跨入口能力仍是产品目标，后续需要逐项验证接入能力，不能仅凭页面设计就认定已经实现。

## 十、怎样逐步装备生活和工作

| 生活领域 | 专业伙伴的工作 | 秘书把它接回个人生活的方式 |
|---|---|---|
| 量化与研究 | 来源审查、研究、回测、持续观察 | 保留研究口径、整合变化与待判断点，跟进交付 |
| 软件与产品 | 需求、开发、验证、发布准备 | 跟进任务与卡点，将成果带回可使用的入口 |
| 内容创作 | 素材、写作、制作、版本与审阅 | 维持角色和作品连续性，安排需用户审阅的部分 |
| 旅行与日常安排 | 收集地点、比较方案、准备事项 | 结合时间和偏好，保留选择与准备进度 |
| 个人事务 | 日程、文件、账单、预约等信息处理 | 帮助记住期限，准备材料，按委托推进 |
| 学习与信息 | 收集、解释、练习、主题跟踪 | 在合适的任务中找回资料，将学到的方法用于下一次 |

这是一组服务方向，不代表已经具备各领域的外部操作能力。领域是否开启，应由真实重复需求驱动。先完成少数高频事情的全过程，再扩大覆盖；无需注册一套空角色和空仪表盘。

片段允许一直只是片段；闲聊允许只是闲聊。系统应帮助用户找回和使用有价值的信息，同时让无关材料自然沉下去，避免把生活变成需要每天清空的任务收件箱。

## 十一、记忆与技能怎样越用越好

记忆积累“关于你和事情的事实”；技能积累“如何把某类事做好”。一次成功可以成为候选经验，重复有效、经过核查的方法才适合稳定复用。相似技能需要合并，过期方法应修订或停用。

角色只调用当前任务相关的技能。新增一个角色、工具或技能，应能指出它解决的真实问题。秘书需要知道谁擅长什么、方法适合哪里，无需把所有专业步骤写进自己的每次对话。

个人积累应可查看、修改、导出并随设备或模型迁移。可迁移内容包括角色说明、个人记忆、任务记录、来源关联与技能文档；能否完整恢复厂商内部会话状态，属于后续要核实的能力。

## 十二、客观研究提供的设计视角

以下研究帮助解释问题与设计取舍。将它们用于本产品属于设计推导，尚不能证明产品会达到预期效果。

### 认知卸载

Risko 与 Gilbert 总结人通过外部行动和工具降低认知需求的研究。对本产品的启发是，让记录、找回、记住未来事项以及恢复工作更容易，评价时看实际减少多少心力。[原文：Cognitive Offloading](https://samgilbert.net/pubs/Risko2016TiCS.pdf)

### 协调理论

Malone 与 Crowston 将协调理解为管理活动间的依赖。由此推导，秘书的价值集中在交接、前后依赖、优先级和成果整合；专业角色增多时，这项服务尤其重要。[原文：The Interdisciplinary Study of Coordination](https://crowston.syr.edu/sites/default/files/acmcs94.pdf)

### 混合主动交互

Horvitz 强调自动服务需要考虑目标不确定性、注意力、打断代价，并支持用户直接发起、停止和修正。产品据此保留秘书主动服务和用户直接找伙伴两条路径，让主动程度随情境变化。[原文：Principles of Mixed-Initiative User Interfaces](https://erichorvitz.com/chi99horvitz.pdf)

### 自动化的功能与程度

Parasuraman、Sheridan 与 Wickens 区分信息获取、分析、选择与实施，并讨论各阶段不同的自动化程度。由此推导，委托应随事情和阶段确定；“全部自动”无法表达所有用户意愿。[原文：A Model for Types and Levels of Human Interaction with Automation](https://pubmed.ncbi.nlm.nih.gov/11760769/)

### 人机协作中的修正与适应

Amershi 等提出并评估了人机交互设计准则，包括便于调用、拒绝、修正，以及结合近期交互、学习行为并谨慎适应。产品据此把低成本纠正和渐进个性化纳入核心体验。[原文：Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)

### 自动化后的监督负担

Bainbridge 讨论工业自动化中可能出现的困难：常规工作被接管后，人却承担难以持续胜任的监视和接管。这里借鉴其视角，要求秘书提供可理解的状态、建议和恢复线索，衡量委托后新增的监督成本。该论文并未直接研究今日的语言模型秘书。[原文：Ironies of Automation](https://gwern.net/doc/sociology/technology/1983-bainbridge.pdf)

## 十三、产品应怎样证明自己帮到了人

核心判断是用户处理真实事情的总负担下降，包括记录、寻找、解释、协调、监督、纠正，以及设置产品本身的成本。

可观察指标包括：恢复一项旧任务需要多久；重复交代背景的频率；用户手动转发消息和追问进度的次数；决定前需要阅读和比较多少材料；保存的片段能否被实际找回使用；纠正后同类问题是否减少；主动提醒是否及时、有用；直接与专业伙伴工作后总览是否准确。

角色数、消息数、保存量和使用时长不能独立代表成功。一个安静且可靠、经常替用户结束事情的产品，也可能减少用户打开它的次数。

## 十四、先验证三个完整情景

1. 周末安排：随手保存两条旅行内容，之后一句“帮我看看周末去哪”，秘书结合当前安排准备选项；用户在手机选定后，电脑能看到同一计划与准备进度。
2. 量化工作：秘书交代研究，用户绕过秘书与量化伙伴调整研究口径；秘书按新口径跟进，汇报时给出成果、局限和下一步，无需用户传话。
3. 跨领域交付：用户提出量化监控页面，量化伙伴确定指标口径，产品伙伴完成页面；秘书协调依赖、验证交付是否满足目标，并保留后续可复用的方法。

通过这三类情景，再决定哪些专业角色与生活领域值得扩展。首版产品应交付可以反复完成的全过程。

## 十五、保留的产品约束

开源；主力 Windows；支持用户自己的手机交互；多电脑和跨 Agent；使用者免部署独立业务服务端；客户端可配对互通；个人记忆可迁移；厂商 CLI／Desktop 与伴随式入口共存。

“装好就能互通”指经过用户配对的个人设备之间可协作，不是任意安装者共享个人信息。实际联网条件、后台能力、接入范围与厂商限制留待技术方案核实。

本文件是产品构想。本轮没有启用新的持续采集、跨设备同步或自动执行。
