# MVP 0.3 验收

本版保留任务看板、角色筛选、列表、对话和成果详情。收敛的是长期人员确认和飞书日常入口。

| 项目 | 验收方式 |
| --- | --- |
| 实际分工与汇总 | 从安装后的工作台提交合成任务。真实 Codex 调用本地接口派出临时协作，用两条独立会话工作。专业结果自动回到原任务，助理生成 HTML。真实浏览器用成果名找回并预览，长期角色数量未变。 |
| 一次确认 | 真实浏览器点击“同意招募”后故意丢掉响应，再点一次。仅创建一位长期协作者，未开通外部机器人。 |
| 网页与飞书共用决定 | 独立数据库中调用实际网页使用的决定逻辑，再注入原生结构的飞书回调。两个入口得到同一角色，旧卡无法反转决定，原卡会更新。 |
| 减员继续交接 | 在有在途任务时确认，验证新派单拦截、原任务结束后自动并回、重启后恢复，以及 0.2 的部分交接迁移。保留原任务 ID 与有范围的记忆。 |
| 飞书点一次继续 | 独立数据库与原生回调结构验证。回执直接提示可发补充，保留同一任务，不另外发送一张中间卡。 |
| 任务与成果查找 | 真实浏览器搜索成果文件名，打开 HTML 预览，从原任务继续。隔离飞书测试覆盖归档任务续聊及个人范围约束。 |
| 角色上下文 | 在同一任务的两条对话放入不同请求和资料，核验专业角色只能拿到本次授权给它的内容。长期偏好按范围和条数取用。 |
| 飞书模板 | 实际飞书发送接口接受两种合成模板，包括待确认卡和查找任务卡。真实客户端点击与独立机器人开通仍需飞书配置。 |

新版在一台已运行 0.2.1 的 Windows 上完成升级，原任务、飞书绑定和资料保留。Windows ZIP 重新解压，以包内 Node 复验 72 项后端、35 项桥接、8 项浏览器、2 项安装器案例，全部通过。
