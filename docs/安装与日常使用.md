# 安装与日常使用

## 已有飞书桥接的 Windows

打开并登录 Codex Desktop，解压完整的 Windows 接入包，双击“安装伴随.cmd”。安装会查找名为 `Codex Feishu Bridge` 的既有启动任务，不会要求重新填已有飞书密钥。非默认位置可以在 PowerShell 中指定：

```powershell
.\scripts\install.ps1 -BridgeRoot "D:\你的桥接目录"
```

成功后双击“启动伴随.cmd”，打开带本机认证的工作台。以后可用托盘图标右键打开工作台，左键只弹出“记一下”。原来的登录自动启动继续拉起桥接和工作台，关闭网页不会停止工作。

程序位于 `%LOCALAPPDATA%\CompanionMVP\app`，资料位于 `%LOCALAPPDATA%\CompanionMVP\data`。安装备份包含私人原配置，只保存在本机的 `backups` 目录，不要作为公开源码分享。

## 新电脑首次配置

源码包包含不带账号数据的 `bridge-kit`，用于建立相同的底层连接。需要 Windows、已登录的 Codex Desktop、Node.js 22.19+、自己的飞书应用机器人。Windows 接入包附带桥接运行时与依赖；源码包的开发者需自行安装依赖。

在 Codex Desktop 中打开解压目录，请 Codex 执行 `bridge-kit/scripts/install.ps1 -NoStart`。首次接入使用当前桌面对话的环境信息，因此应由 Codex Desktop 中的终端运行，而不是从任意外部终端猜测会话编号。

配置窗口填写自己的飞书 App ID 与 App Secret。飞书应用需启用机器人、长连接事件、接收消息与回复所需权限，权限参考 `bridge-kit/scripts/feishu-scopes.json`；发布应用后才会生效。桥接密钥使用当前 Windows 账户加密，不放入源码。

在安装后的桥接目录运行 `src/pairing.mjs` 会显示一次性绑定口令，按屏幕提示向自己的机器人私聊发送。接着启动桥接、确认可用，再安装本工作台。该流程建立的是用户自己设备与自己账号的连接，没有代替用户申请飞书应用或登录模型账户。

## 连接 Android

在飞书发送 `/安装包`，或从工作台“连接手机”下载 APK。安装后，在电脑生成一次性配对信息；手机“连接”页可粘贴整条飞书回复。成功后直接记录或从系统分享菜单选“记一下”。

同一 Wi-Fi 使用本地地址。已经在电脑和手机上使用 Tailscale 时，选择对应私网地址，或在飞书发送 `/连接手机 Tailscale`。本项目不会代为注册、安装或变更 Tailscale。

如果手机连接超时，先确认电脑醒着、原桥接在运行、手机能到所选地址。Windows 防火墙可能拦截手机登记端口 `47472`；需要在系统中允许实际桥接 Node 程序的相应本地网络连接。工作台端口 `47471` 只在本机使用，无需对外开放。

Android 后台同步由系统调度，省电策略可能延后。立即打开“记一下”会触发同步。某条内容永久失败会单独暂停，点击重试后继续，不会拦住其余记录。

## 日常接续

工作台提交后会进入该事项聊天。打开“进展与成果”看真实状态和文件，打开“在 Codex 中打开”可以回到原生对话。原生读接口的列表与消息会有短暂延迟，必要时点刷新。

飞书先 `/任务` 找编号，再 `/切换 编号`，之后直接发消息就继续同一事项。`/新任务` 会单独建立一个目标。个人资料检索和配对等命令不会生成模型任务。

记录不会自动变成待办。需要用于某次工作时，在资料页勾选后回首页交代；专业伙伴只获取本次分配的资料。关于个人的明确偏好可在“关于我的理解”登记；误解可以修正或停用。

## 导出、更新与撤回

“数据与连接 → 导出个人资料包”下载普通 ZIP。`companion.json` 保留有范围的记忆、已保存公开消息和事项，`materials` 是资料附件，`artifacts` 是实际成果。用户原文保留，分享导出包前自行判断内容范围。

再次安装会更新程序并保留数据。原任务尚未结束时安装会等待，不会强行中断模型。安装遇到兼容错误会恢复原桥接；不要通过手改队列清除不确定状态来重复执行。

双击“恢复原桥接.cmd”可撤回工作台接入，保留资料与记忆。存在未完成本地工作或未发送本地回执时会阻止撤回。退出托盘图标只关闭轻入口，不会停止飞书或正在进行的工作。
